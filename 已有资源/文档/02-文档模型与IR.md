# 文档模型与 docparse IR

> 来源：`任务二/vendor/docparse/docparse/ir.py`、
> `任务二/vendor/docparse/docs/output-formats.md`、
> `任务二/vendor/docparse/docs/architecture.md`。
> 可复用实现：`代码/document_model.py`、`代码/chunking.py`。

## 1. 为什么要分两层模型

原项目把“解析结果”和“检索片段”分开：

- **IR（中间表示）**：保留版面结构，回答“这页有什么、在哪里”；
- **Chunk**：检索的最小单位，回答“这段文字属于哪一节、哪一页、哪个文件”。

课程项目的 Connector 只需要产出统一 `Document`；切块器再根据 IR 或纯文本产出
`Chunk`。这样新增一种数据源（TXT、Markdown、HTML、PDF）不需要改检索核心。

## 2. docparse IR 结构

```jsonc
{
  "path": "invoice.pdf",
  "sha256": "…",
  "doc_type": "pdf",
  "needs_review": false,
  "warnings": [
    { "code": "low_coverage", "severity": "medium", "message": "…" }
  ],
  "meta": {
    "pages_total": 3,
    "kie": [ { "page": 1, "json": {…}, "grounding": {…} } ]
  },
  "pages": [
    {
      "number": 1,
      "width": 1240,
      "height": 1754,
      "kind": "scanned",          // native | scanned | hybrid | blank | image
      "mode": "region",           // native | page | region | failed
      "warnings": [],
      "latency_ms": 7021,
      "usage": { "prompt_tokens": 1503, "completion_tokens": 304 },
      "blocks": [
        {
          "id": "p1b0",
          "page": 1,
          "type": "table",        // title|text|table|formula|figure|page|page_markdown
          "bbox": [131, 210, 840, 519],
          "reading_order": 0,
          "content": "<table>…</table>",
          "html": "<table>…</table>",
          "source": "vlm_region", // native_text|vlm_page|vlm_region|layout|native_office
          "confidence": 1.0,
          "warnings": [],
          "meta": { "layout_label": "table", "layout_score": 0.97 }
        }
      ]
    }
  ]
}
```

### 关键字段

| 字段 | 含义 | 对检索的作用 |
| --- | --- | --- |
| `bbox` | 归一化到 0–1000 的 `[x1,y1,x2,y2]` | 跨 DPI 稳定，可映射回页面做引用截图/高亮 |
| `source` | 内容来源：原生文本层、整页 OCR、区域 OCR、Office 原生解析 | 判断可信度与是否需要复核 |
| `confidence` | 启发式分数，不是模型概率 | 只作辅助；可信信号优先看 `warnings` |
| `warnings` | 机器可读告警（重复、截断、空输出、表格解析失败等） | 质量门依据 |
| `reading_order` | 页内阅读顺序 | 切块排序 |
| `type` | block 类型 | 标题进 section_path，表格/公式整块保留 |

### `kind` 与路由

| kind | 判据 | 处理 |
| --- | --- | --- |
| `native` | 字符数 ≥ 10、乱码率 ≤ 5%、图像覆盖 < 30% | PyMuPDF 原生抽取，不调模型 |
| `hybrid` | 文本层健康，但图像覆盖 > 30% | 原生抽取 + 图像块 |
| `scanned` | 无文本层 / 乱码率高 / 整页大图 | 渲染后送 VLM OCR |
| `blank` | 无文字且无图像 | 跳过 |

原则：**有健康文本层的页绝不送 OCR**。OCR 只会引入新错误，而且慢两个数量级。

## 3. 输出格式

所有输出都是 IR 的序列化视图，解析逻辑不依赖具体格式：

| 格式 | 内容 | 课程项目用途 |
| --- | --- | --- |
| `.md` | 正文 Markdown，表格为 HTML `<table>`，公式为 LaTeX，多页用 `<!-- page N -->` 分隔 | 人读、喂给 LLM、作为 Markdown Connector 的输入 |
| `.json` | 完整 IR，含 page/bbox/source/confidence/warnings | 切块、引用高亮、审计 |
| `.html` | 独立 HTML，内嵌样式，表格原样保留 | 浏览器预览 |
| `.txt` | 纯文本，HTML 表格转制表符分隔 | 全文检索、旧系统 |

设计约束：**格式是序列化器，不能反向影响解析**。新增格式只实现 `(Document) -> str|bytes`。

## 4. 课程项目的统一模型

`代码/document_model.py` 提供两个核心数据结构：

```python
@dataclass
class Document:
    doc_id: str          # sha256(相对路径)[:12]
    source: str          # 相对路径或 URI，检索结果必须回显
    content: str         # 归一化正文
    title: str = ""
    media_type: str = "text/plain"
    metadata: dict = {}  # sha256、页数、解析器信息等
    segments: list[dict] = []  # 可选：保留原始段落/版面结构

@dataclass
class Chunk:
    id: str              # sha1(doc_id:类型:序号)[:20]
    doc_id: str
    text: str
    source: str
    index: int
    content_type: str = "text"   # text | table | code | formula | figure | page_text
    section_path: str = ""       # "1 Introduction > 1.2 Method"
    page: int = 0
    page_end: int = 0
    bbox: str = ""               # JSON 字符串，如 "[131,210,840,519]"
    block_ids: list[str] = []
    metadata: dict = {}
```

### Connector 的职责边界

| 层 | 负责 | 不负责 |
| --- | --- | --- |
| Connector（TXT/Markdown/PDF/HTML） | 读取数据源，产出 `Document` 或 `(Document, IR)` | 不切块、不检索、不写索引 |
| Chunker | 把 `Document`/IR 切成 `Chunk` | 不读文件、不访问网络 |
| Index | 建立倒排/向量索引，按 `doc_id` 幂等更新 | 不解析原始格式 |
| Search | 查询、排序、返回带来源的命中 | 不关心数据源类型 |

这条边界就是课程要求里的“公开接口约定”：核心不应该按数据源类型不断增加分支。

## 5. 从 IR 映射到 Document / Chunk

`代码/docparse_connector.py::document_from_ir` 已经实现了映射：

```python
from docparse_connector import document_from_ir
from chunking import chunk_docparse_ir

doc = document_from_ir(ir, "papers/attention.pdf", content=markdown)
chunks = chunk_docparse_ir(ir, doc)
```

对应关系：

| IR | Document / Chunk |
| --- | --- |
| `ir["sha256"]` | `Document.metadata["sha256"]`（原文件哈希） |
| `ir["pages"]` | `Document.metadata["pages"]` |
| 第一个 `type="title"` 的 block | `Document.title`（缺失时用文件名） |
| `pages[].blocks[].content/html` | 拼接为 `Document.content`（有 Markdown 时优先用 Markdown） |
| `page.number` | `Chunk.page` / `page_end` |
| `block.bbox` | `Chunk.bbox`（JSON 字符串） |
| `block.id` | `Chunk.block_ids` |
| 标题栈 | `Chunk.section_path` |
| `type=table/formula/figure` | `Chunk.content_type`，整块保留 |

## 6. 引用与可追溯

检索命中至少应返回：

```json
{
  "doc_id": "a1b2c3d4e5f6",
  "source": "papers/attention.pdf",
  "title": "Attention Is All You Need",
  "page": 3,
  "section_path": "3 Model Architecture > 3.2 Attention",
  "content_type": "text",
  "text": "…",
  "score": 0.87
}
```

如果保留 `bbox`，还能进一步做“原文截图高亮”：把 0–1000 的归一化坐标映射回
PDF 页面或图片，裁剪出命中区域。原项目的 `ocr_service.py::render_citation`
就是这个思路；课程项目不做截图也可以，但 `source + page + section_path` 必须保留。

## 7. 设计取舍

| 选择 | 理由 | 代价 |
| --- | --- | --- |
| IR 与 Chunk 分离 | 解析格式变化不影响检索；引用信息不丢失 | 多一层数据结构，代码略多 |
| bbox 归一化到 0–1000 | 跨 DPI/缩放稳定 | 需要渲染端按页面尺寸换算 |
| `confidence` 只作辅助 | 模型自报分数不可靠 | 质量判断更依赖 warnings 和启发式 |
| Markdown 作为人读视图 | 简单、通用、可喂 LLM | 表格用 HTML，纯文本阅读体验一般 |

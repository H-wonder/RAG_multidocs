# 切块与去重

> 来源：`任务二/docflow/chunker.py`、`任务二/docflow/dedup.py`、
> `tests/test_docflow_chunker.py`、`tests/test_docflow_dedup.py`。
> 可复用实现：`代码/chunking.py`、`代码/dedup.py`、`代码/tests/`。

## 1. 切块目标

课程项目里的切块不只是“每 500 字切一刀”，它要同时满足：

1. **可检索**：块不要太大，否则一个块里混入多个主题；也不要太小，否则上下文不足；
2. **可复现**：同样的输入永远切出同样的块和同样的 id，方便增量索引；
3. **可溯源**：每块带文件名、页码、章节路径，命中后能指回原文；
4. **不破坏结构**：表格、公式、代码块整块保留，不能被字符数腰斩。

原项目的做法是：**按版面结构切，再按 token 预算装箱**。

## 2. Token 预算

不引入 tokenizer，用启发式估计：

```python
def estimate_tokens(text: str) -> int:
    cjk = 中文字符数
    words = 英文/数字词数
    raw = cjk + len(words) * 1.35 + other * 0.4 + 1
    return int(raw * 1.3)      # 安全系数
```

- 中文约 1 字 1 token；
- 英文约 4.2 字 1 token；
- 乘以 1.3 是基于 bge-small-zh 分词器在 47 个真实 chunk 上的校准：
  实际/估计的 p95 = 1.21、最大 = 1.28，所以估出来的是上界。

默认参数（`代码/chunking.py::ChunkingOptions`）：

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `max_tokens` | 480 | 装进 bge-small 的 512 上下文；换大模型可放宽 |
| `overlap_tokens` | 60 | 块间重叠，避免上下文被切断 |
| `max_table_rows` | 60 | 表格最多保留的行数，超出截断并注明 |

切分顺序：

1. 段落超过预算 → 按句末标点（`。！？!?；;`）切；
2. 单句仍超预算 → 按 token 预算硬切；
3. 装箱时如果“上一块尾部 + 新段”超过预算 → 放弃重叠，保证不超限。

## 3. 结构化切块

### 3.1 标题与 section_path

- 标题块不进入正文，而是压入标题栈，形成 `"1 Introduction > 1.2 Method"`；
- 同级标题替换，子级清空；
- 没写章节号时，用 bbox 高度辅助判断：明显比正文高、且文本短 → 标题；
- 含 `arxiv/doi/http/@/年份` 的短文本不当标题，避免把页眉、编号、作者行误判。

### 3.2 页眉/页脚过滤

跨页重复出现的短文本（≤120 字符）如果出现在至少 3 页、且覆盖一半以上页面，
判为页眉/页脚并丢弃。例外：带章节号的标题每页也会重复，不能删。

只有页数 ≥ 3 才启用，避免把两页文档里正常的重复句误删
（对应测试 `test_short_document_keeps_repeated_line`）。

### 3.3 表格

- HTML 表格转成 `a | b | c` 的行文本，整块作为一个 chunk；
- 行被切开就没法读，所以**不交给字符切分器**；
- 超过 `max_table_rows` 行时截断，并在文本末尾注明原行数。

### 3.4 公式与图注

- `formula` / `figure` 各自成块，`content_type` 保留原类型；
- 图注如果被解析成 `figure` 的 content，会和图放在一起，不会散落到正文。

### 3.5 确定性 chunk id

```python
chunk_id = sha1(f"{doc_id}:{location}:{content_type}:{counter}")[:20]
```

- 同一文档重跑 → 同一批 id；
- 索引层按 `doc_id` 先删后插 → 不产生重复；
- 不同文档即使内容相似，id 也不同（doc_id 不同）。

## 4. Markdown 切块

`代码/chunking.py::chunk_markdown` 是给课程项目的 Markdown Connector 用的：

- `#`~`######` 进入 `section_path`，标题行本身不进正文；
- 围栏代码块（``` / ~~~）整块保留，内部出现的 `#` 不会被当成标题；
- 连续以 `|` 开头的行视为 Markdown 表格，整块保留；
- 其余按空行分段，再按 token 预算装箱。

示例：

````markdown
# Intro

alpha paragraph

## Detail

beta paragraph

```python
# 这不是标题
print("hi")
```

| 项目 | 数量 |
| --- | --- |
| 螺丝 | 2 |

# End

gamma paragraph
````

切块结果：

| text | content_type | section_path |
| --- | --- | --- |
| alpha paragraph | text | Intro |
| beta paragraph | text | Intro > Detail |
| ```python ...``` | code | Intro > Detail |
| 项目 \| 数量 ... | table | Intro > Detail |
| gamma paragraph | text | End |

## 5. 纯文本切块

`chunk_text` 按空行分段，再装箱；没有章节结构。适合课程最低要求的 TXT Connector。
如果 TXT 里有手工写的 `第 1 章`/`1. Introduction`，可以在 Connector 里先转成
Markdown 标题，再走 `chunk_markdown`，不需要改核心。

## 6. SimHash 去重

### 6.1 算法

1. 文本转小写，抽出中文单字 + 英文/数字词；
2. 切成 3-gram（shingle），统计词频；
3. 每个 gram 用 MD5 取前 64 位，按词频加权：该位为 1 加权重，否则减权重；
4. 每一位权重 > 0 记 1，得到 64 位指纹（16 位十六进制）。

### 6.2 阈值

| 变化 | 汉明距离（实测） |
| --- | --- |
| 同一文本 | 0 |
| 改一个词 | 约 8 |
| 加一句话 | 约 15 |
| 无关文档 | 30 以上 |

默认阈值 **10**：改一个词仍判近重复，无关文档不会误判。
阈值与语料、语言有关，上线前应用自己的样例校准。

### 6.3 使用规则

- 只把 **INDEXED** 的文档作为去重基准；
- 不要把 DUPLICATE / FAILED 的指纹也纳入比较，否则两份重复文件会互相判重，
  最后一份都进不了库；
- 同一批次内也要互查（原项目在 `split_docs` 里做）；
- 去重是“跳过索引”，不是删除文件；清单里保留 `DUPLICATE` 状态和最近匹配的 doc_id。

## 8. 对课程项目的建议

| 要求 | 建议 |
| --- | --- |
| 核心 TXT Connector | 用 `chunk_text`，默认参数即可 |
| 独立 Markdown Connector | 用 `chunk_markdown`，保留 section_path |
| 检索结果带来源 | 至少返回 `source + page + section_path`；有 IR 时再加 bbox |
| 去重 | 可作为核心的加分能力；测试成本低，演示“重复资料不会重复入库”很直观 |
| 向量检索 | 非必需；先做关键词/BM25，再考虑 Milvus |

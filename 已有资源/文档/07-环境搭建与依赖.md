# 环境搭建与依赖

> 面向第一次配置本项目的开发者。按本文可以从零搭起“插件平台 + 多模态文档解析 + RAG”
> 的运行环境。
>
> 默认使用**两个 conda 环境**：`rag`（平台）和 `docparse`（解析）。
> 平台通过子进程调用解析环境，不 import docparse；两边依赖互不污染。
> Milvus 用 Docker，Ollama 作为宿主机服务。

## 0. 组件与运行方式

```text
┌──────────── rag conda env (Python 3.11) ────────────┐
│  CLI / Core                                                 │
│  ├── 文档模型、Connector 注册表、入库编排                     │
│  ├── Connector：TXT、Markdown（独立扩展）                    │
│  ├── PDF/扫描件/Office Connector ──子进程──┐                 │
│  ├── 索引：Milvus 混合检索（主）/ 关键词倒排（回退）          │
│  └── 检索、来源输出、测试                                    │
└───────────────┬──────────────────────────────┬─────────────┘
                │ pymilvus                     │ subprocess
                ▼                              ▼
┌──────── Docker Milvus ────────┐   ┌──── docparse conda env ────┐
│ milvus-standalone             │   │ docparse CLI / Parser      │
│ milvusdb/milvus:v2.5.6        │   │ PyMuPDF、PaddleX、OCR       │
│ :19530 / :9091                │   └──────────────┬─────────────┘
└───────────────────────────────┘                  │ loopback HTTP
                                                   ▼
                                    ┌──────── 宿主机 Ollama ────────┐
                                    │ longwayxu/xiaomi-ocr-0:bf16   │
                                    └───────────────────────────────┘
```

| 组件 | 环境/形态 | 职责 | 是否必需 |
| --- | --- | --- | --- |
| CLI / Core / Connector / 索引 / 检索 / 测试 | `rag` conda env | 平台主体 | 必需 |
| TXT、Markdown Connector | `rag` | 基础接入与独立扩展 | 必需 |
| PDF/扫描件/Office 解析 | `docparse` conda env，子进程 | 多模态接入 | 多模态功能必需 |
| Milvus | Docker | 向量 + BM25 | RAG 主检索；可回退关键词 |
| Ollama | 宿主机进程 | OCR 模型 | 有扫描件/图片时必需 |
| Attu | Docker（可选） | 查看集合与数据 | 可选 |

**为什么不合并成一个环境**：两个依赖栈有大量同名包版本不同（numpy、pandas、
protobuf、fastapi、pydantic、PyMuPDF、Pillow 等），paddle 和 torch 还带可能冲突的
OpenMP/MKL 库。分开可以避免这些冲突，也便于单独重装解析器。平台只通过子进程
调用 docparse，所以解析环境不需要和平台共享依赖。

### 从零开始的执行顺序

1. 安装 Miniconda、Docker、Ollama（第 1 节）；
2. 运行 `bash 环境/setup.sh`，创建 `rag` + `docparse` 两个环境（第 2 节）；
3. 复制 `.env.example` 为 `.env`，把 `DOCPARSE_PYTHON` 指向 `docparse` 环境（第 3 节）；
4. 启动 Milvus 容器和 Ollama（第 4 节）；
5. 跑测试和样例，确认 `37 passed`（第 2.3 节）；
6. 导入一个 TXT/PDF，执行一次检索，确认命中带来源（第 8 节）。

## 2. 安装双环境（默认方案）

### 2.1 一键安装

在包含 `已有资源/` 的目录执行：

```bash
cd 已有资源
bash 环境/setup.sh
```

脚本会：

1. 创建平台环境 `rag`（Python 3.11），安装 torch + `requirements-rag.txt`
   + `requirements-core.txt`；
2. 创建解析环境 `docparse`（Python 3.11），安装 `requirements-docparse.txt`
   + paddlepaddle/paddlex；
3. 分别执行 `pip check` 与 import 验证。

自定义环境名或 CUDA：

```bash
PLATFORM_ENV=my-rag PARSER_ENV=my-docparse \
TORCH_INDEX_URL=https://download.pytorch.org/whl/cu124 \
bash 环境/setup.sh
```

### 2.2 手动安装

```bash
# 平台环境
conda create -y -n rag -c conda-forge python=3.11
conda activate rag
pip install torch==2.6.0 --index-url https://download.pytorch.org/whl/cpu
pip install -r 已有资源/环境/requirements-rag.txt
pip install -r 已有资源/环境/requirements-core.txt

# 解析环境
conda create -y -n docparse -c conda-forge python=3.11
conda activate docparse

pip install paddlepaddle==3.3.1
pip install "paddlex[cv]==3.7.2" shapely==2.2.0
pip check
```

### 2.4 两个环境的边界

| 环境 | 可以 import | 不应该 import |
| --- | --- | --- |
| `rag` | pymilvus、sentence-transformers、平台核心、Connector 契约 | paddle、paddlex、docparse |
| `docparse` | docparse、PyMuPDF、paddle、paddlex | pymilvus、sentence-transformers |

平台调用解析器的唯一入口是 `DocparseConnector`，它启动子进程执行
`DOCPARSE_PYTHON -m docparse ...`，然后读取 IR JSON。这样：

- 解析器崩溃/超时不会拖垮平台进程；
- 重装 paddle 不需要动平台环境；
- 单文件失败可以转成 `PARSE_ERROR`，其他文档继续。

## 3. 配置

### 3.1 创建 `.env`

```bash
cd 项目根目录
cp 已有资源/环境/.env.example .env
# 按实际路径修改 DOCPARSE_REPO、DOCPARSE_PYTHON、MILVUS_URI 等
set -a; source .env; set +a
```

`.env` 不要提交到仓库；课程 ZIP 只保留 `.env.example`。

### 3.2 平台配置

| 变量 | 默认 | 作用 |
| --- | --- | --- |
| `RAG_DATA_DIR` | `./data` | 平台数据根目录 |
| `RAG_INDEX_DIR` | `./data/index` | 关键词索引落盘 |
| `RAG_MANIFEST` | `./data/manifest.db` | 增量清单（可选） |
| `CONNECTORS_DIR` | `./connectors` | Connector 插件目录 |

| `CONNECTOR_TXT_ENABLED` | `true` | 内置 TXT Connector |
| `CONNECTOR_MARKDOWN_ENABLED` | `true` | 独立 Markdown 扩展 |
| `CONNECTOR_PDF_ENABLED` | `true` | 内置 docparse Connector |

### 3.3 docparse 配置

| 变量 | 默认/建议 | 作用 |
| --- | --- | --- |
| `DOCPARSE_REPO` | `./已有资源/可选组件/docparse` | 含 `docparse/` 包的目录 |
| `DOCPARSE_PYTHON` | `conda run -n docparse which python` 的结果 | 解析环境 Python |
| `DOCPARSE_MODE` | `auto` | `auto` / `page` / `region` |
| `DOCPARSE_TIMEOUT_S` | `1800` | 单文件解析超时 |
| `DOCPARSE_LAYOUT_DEVICE` | `cpu` | PP-DocLayoutV3 设备：`cpu` 或 `gpu:0` |
| `PADDLE_PDX_DISABLE_MODEL_SOURCE_CHECK` | `True` | 离线/源检查慢时跳过 |
| `TOKENIZERS_PARALLELISM` | `false` | 避免 tokenizer 并发警告 |

### 3.4 Ollama 配置

| 变量 | 默认 | 作用 |
| --- | --- | --- |
| `OLLAMA_URL` | `http://127.0.0.1:11434` | 平台侧健康检查/调用 |
| `OLLAMA_HOST` | `127.0.0.1:11434` | 服务监听地址，保持 loopback |
| `OLLAMA_CONTEXT_LENGTH` | `16384` | 整页图片约 2–4k vision token，默认 4096 会截断 |
| `OLLAMA_NUM_PARALLEL` | `1` | 避免并发 OOM |
| `OLLAMA_KEEP_ALIVE` | `30m` | 模型驻留时间 |
| `OLLAMA_MAX_LOADED_MODELS` | `1` | 只保留 OCR 模型 |
| `XIAOMI_OCR_MODEL` | `longwayxu/xiaomi-ocr-0:bf16` | OCR 模型，首次约 1.8GB |
| `XIAOMI_OCR_LOCAL_URL` | `http://127.0.0.1:11434/v1` | docparse 使用的 OpenAI 兼容地址 |

docparse 的 `backend.py` 只允许 loopback 地址，不要改成远程 URL。

## 4. 外部服务

### 4.1 Ollama

```bash
# 推荐用项目自带脚本：会设置上下文长度、并发和模型
cd 已有资源/可选组件/docparse
bash scripts/start_ollama.sh

# 或手动
export OLLAMA_CONTEXT_LENGTH=16384
export OLLAMA_NUM_PARALLEL=1
ollama serve
ollama pull longwayxu/xiaomi-ocr-0:bf16
```

验证：

```bash
ollama list
ollama ps
curl -s http://127.0.0.1:11434/api/tags | head
```

GPU/CPU：默认使用 Ollama 可见的设备；显存不足会退化到 CPU。多卡可用
`CUDA_VISIBLE_DEVICES` 选择。布局模型默认在 CPU，把显存留给 OCR。

### 4.2 Milvus（Docker）

推荐单容器形态：embedded etcd + 本地存储。配置模板在 `环境/milvus/`。

```bash
# 1. 准备目录和配置
export MILVUS_HOME="$HOME/milvus"        # 可改成任意目录
mkdir -p "$MILVUS_HOME/volumes/milvus"
cp 已有资源/环境/milvus/embedEtcd.yaml "$MILVUS_HOME/"
cp 已有资源/环境/milvus/user.yaml "$MILVUS_HOME/"

# 2. 启动
docker run -d --name milvus-standalone \
  --security-opt seccomp:unconfined \
  -e ETCD_USE_EMBED=true \
  -e ETCD_DATA_DIR=/var/lib/milvus/etcd \
  -e ETCD_CONFIG_PATH=/milvus/configs/embedEtcd.yaml \
  -e COMMON_STORAGETYPE=local \
  -e DEPLOY_MODE=STANDALONE \
  -v "$MILVUS_HOME/volumes/milvus:/var/lib/milvus" \
  -v "$MILVUS_HOME/embedEtcd.yaml:/milvus/configs/embedEtcd.yaml" \
  -v "$MILVUS_HOME/user.yaml:/milvus/configs/user.yaml" \
  -p 19530:19530 -p 9091:9091 -p 2379:2379 \
  --health-cmd "curl -f http://localhost:9091/healthz" \
  --health-interval 30s --health-timeout 20s \
  --health-start-period 90s --health-retries 3 \
  milvusdb/milvus:v2.5.6
```

`embedEtcd.yaml`：

```yaml
listen-client-urls: http://0.0.0.0:2379
advertise-client-urls: http://0.0.0.0:2379
quota-backend-bytes: 4294967296
auto-compaction-mode: revision
auto-compaction-retention: '1000'
```

其他形态：

- 官方 standalone compose（etcd + MinIO + standalone 三容器）：从 Milvus release
  页面下载 `milvus-standalone-docker-compose.yml` 后 `docker compose up -d`；
- 版本必须 **Milvus 2.5+**，BM25 Function 是 2.5 才有的；
- Attu 可选：
  `docker run -d --name attu -p 8000:3000 --add-host=host.docker.internal:host-gateway -e MILVUS_URL=http://host.docker.internal:19530 zilliz/attu:v2.5`，
  访问 `http://localhost:8000`。

验证与启停：

```bash
docker start milvus-standalone
docker ps --filter name=milvus
docker logs --tail 30 milvus-standalone
curl -s http://localhost:9091/healthz     # 期望 OK/200
docker stop milvus-standalone             # 数据保留在 $MILVUS_HOME
```

端口：

| 端口 | 用途 |
| --- | --- |
| 19530 | SDK 连接（`MILVUS_URI`） |
| 9091 | 健康检查 / metrics |
| 2379 | embedded etcd 客户端（容器内部用） |

## 5. docparse 验证与调用

```bash
conda activate docparse
cd 已有资源/可选组件/docparse

# 检查 Ollama / 模型 / 版面库 / 依赖
PYTHONPATH=$PWD python -m docparse doctor

# 解析一个文件
PYTHONPATH=$PWD python -m docparse parse /path/to/sample.pdf \
  -o /tmp/docparse_out --format md,json --mode auto

# region 模式（印刷表格/密集公式）
PYTHONPATH=$PWD python -m docparse parse /path/to/table.pdf \
  -o /tmp/docparse_out --format md,json --mode region
```

`region` 模式首次运行会下载 PP-DocLayoutV3（约 126MB）到
`~/.paddlex/official_models/PP-DocLayoutV3/`。下载慢时：

```bash
export PADDLE_PDX_DISABLE_MODEL_SOURCE_CHECK=True
```

平台侧调用示例：

```bash
conda activate rag
cd 已有资源/代码

export DOCPARSE_REPO="$PWD/../可选组件/docparse"
export DOCPARSE_PYTHON="$(conda run -n docparse which python)"

python - <<'PY'
import os
from docparse_connector import DocparseConnector, DocparseOptions
from chunking import chunk_docparse_ir

connector = DocparseConnector(DocparseOptions(
    repo=os.environ["DOCPARSE_REPO"],
    python=os.environ["DOCPARSE_PYTHON"],
    mode="auto",
))
doc, ir = connector.parse("/path/to/sample.pdf", "/tmp/docparse_out")
chunks = chunk_docparse_ir(ir, doc)
print(doc.title, len(chunks))
PY
```

注意：

- docparse CLI 入口会先 ping Ollama，即使当前页走原生抽取；如果只想解析纯文本 PDF
  且不想启动 Ollama，需要在 Connector 里直接调用 `docparse.pipeline.Parser`；
- 扫描件/图片必须启动 Ollama 并拉取 OCR 模型；
- `DOCPARSE_REPO` 指向包含 `docparse/` 包的目录，不要指向 `docparse/docparse/`。

## 7. 常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `Model endpoint must be loopback` | `XIAOMI_OCR_LOCAL_URL` 不是 127.0.0.1/localhost | 改回 loopback |
| `Cannot reach .../models` | Ollama 没启动 | `bash scripts/start_ollama.sh` |
| `maximum context` 400 | 图片太大 / 上下文不够 | 保持 `OLLAMA_CONTEXT_LENGTH=16384`，降 DPI 或改 region |
| `layout: not installed` | 解析环境没装 paddle/paddlex | 在 `docparse` 环境重装 `requirements-docparse.txt` 和 paddle |
| paddle 装不上 | 当前平台/架构不受支持 | 解析环境只保留 PyMuPDF/Office；扫描件 OCR 换 Linux + Ollama |
| `paddle` import 失败 | 平台环境里没装 paddle（正常） | 到 `docparse` 环境验证；平台只走子进程 |
| Milvus 连接失败 | 容器未启动/端口不对 | `docker start milvus-standalone`，检查 `MILVUS_URI` |
| 维度不匹配 | 换嵌入模型复用了旧集合 | 新建集合，不要混用不同维度 |
| 模型下载慢 | HuggingFace 默认源 | 设 `HF_ENDPOINT=https://hf-mirror.com` |
| `DOCPARSE_PYTHON` 指向错误 | 指向了平台环境 | 改成 `conda run -n docparse which python` 的结果 |
| docparse 子进程超时 | 大文档/冷启动 | 提高 `DOCPARSE_TIMEOUT_S`，先预热 Ollama |

## 8. 自检清单

```bash
# 0) 环境自检
bash 环境/check_env.sh

# 1) 平台环境
conda activate rag
cd 已有资源/代码 && python -m pytest -q
cd ../样例 && python demo_rag.py
python demo.py
python -c "import pymilvus, sentence_transformers; print('platform ok')"

# 2) 解析环境
conda activate docparse
cd 已有资源/可选组件/docparse
PYTHONPATH=$PWD python -m docparse doctor
cd ../../样例
python demo_docparse.py /path/to/sample.pdf   # 需要 PDF

# 3) Milvus
docker start milvus-standalone >/dev/null 2>&1 || true
curl -s http://localhost:9091/healthz && echo "milvus ok"
python demo_milvus.py                         # 当前在 样例/；可选冒烟

# 4) 端到端
#    平台导入一个 PDF，再查询，确认命中带 source/page/section_path
```

平台核心不 import docparse；docparse 不可用时，TXT/Markdown 接入和关键词检索仍可用。
Milvus 不可用时，平台应回退到关键词倒排，并在结果里标注 `index=keyword`。

## 9. 文件说明

| 文件 | 用途 |
| --- | --- |
| `环境/setup.sh` | 一键创建平台 + 解析两个环境 |
| `环境/check_env.sh` | 环境自检（工具、环境、依赖、服务），不安装 |
| `环境/requirements-rag.txt` | 平台环境依赖（Milvus + 嵌入） |
| `环境/requirements-core.txt` | 平台测试工具（pytest/ruff/jsonschema） |
| `环境/requirements-docparse.txt` | 解析环境依赖 |
| `环境/milvus/embedEtcd.yaml` / `user.yaml` | Docker 单容器部署配置 |
| `环境/.env.example` | 配置模板，复制为项目根目录 `.env` |

`.env.example` 里的路径都是占位符或项目内相对路径，复制后按实际目录修改；
不要把真实 `.env`、API Key、模型权重、缓存打进球 ZIP。
